# Guided tour dock — gMatch (apps/desktop)

Date: 2026-09-11 05:50 (-0300). Repo: `I:/goongrid`, app: `apps/desktop` (Electron + React 19 + Vite + vitest + tailwind).
Mode: ponytail. No new dependencies. Reuse existing patterns only.

## Goal

A floating, non-blocking dock that walks a new user through the app's main features
(teleporting between views on click), resumable, skippable, so people find the good
stuff before churning — without any modal wall that scares anyone off.

## Current context (verified, cite-ready)

- Views are a single state in `src/App.tsx`: `const [mainView, setMainView] = useState<MainViewType>` (App.tsx:182).
  `MainViewType = 'feed' | 'games' | 'create' | 'messages' | 'profile' | 'game' | 'gallery' | 'store' | 'pc_domination' | 'grid' | 'rooms' | 'servers' | 'admin'`
  (`src/components/home/HomeFooter.tsx:20`).
- The ONE teleport entry point is `handleSetMainView` (App.tsx:295): closes chat, syncs URL hash, sets view.
  Games sub-tabs via `setGamesSubTab` (App.tsx:205: `'duel' | 'cards' | 'babecock' | 'ranks' | 'store' | 'idle'`).
  Notifications open via `openNotificationsOnDesktop` (App.tsx:~338). Settings is a modal (`GMatchSettingsModal`),
  opened from SidebarNav callback — the tour does NOT auto-open modals (that's the "scary" part; it just points).
- First-run flow lives in `src/firstRun/` (`OnboardingFlow.tsx`, `onboardingState.ts`). State pattern to copy:
  versioned JSON in localStorage keyed by identity (`orbit_onboarding_v2:<id>`), pure helpers, try/catch reads.
  `wipeUserStorage()` (`src/hooks/useIdentity.ts`) prefix-scans `orbit_onboarding_v2:*` + `SERVER_MARKER_KEY`
  on logout — the tour key MUST be added to that scan (Task 4) or logout leaks tour state.
- No tour lib installed (`react-joyride`, `driver.js` absent from package.json). Do not add one: the dock never
  overlays the page with a spotlight/scrim, it just sits in a corner. That's ~150 lines of our own code,
  zero deps, zero conflict with the wallpaper/dim logic in App.tsx.
- Design contract: `docs/DESIGN.md` — tokens only (`bg-retro-panel`, `border-border-glass`, `text-retro-*`,
  `bg-glass-w10`), ZERO `*-zinc-*` literals, z-scale via `z-[var(--z-toast)]` (toast=70; the dock is system-adjacent
  but must sit UNDER lightboxes/modals per the coexistence rule — use `--z-toast`), 3 durations (150/300/700),
  lucide icons only, no emoji chrome, 10px legibility floor.
- Test env pitfall (from repo skill): under jsdom `localStorage` can be undefined → stub with a Map-backed
  Proxy (needs `ownKeys` + `getOwnPropertyDescriptor` traps because code may scan keys). See
  `src/hooks/useIdentity.test.ts` for the Proxy recipe.
- Parallel agent (opencode) may share the worktree: commit ONLY explicit paths, never `git add -A`.

## Architecture

Three pieces, one direction of dependency:
1. `src/firstRun/tourState.ts` — pure module: step list (data), read/write/advance logic, localStorage persistence
   keyed by identity. Fully unit-testable, no React.
2. `src/components/tour/TourDock.tsx` — dumb floating card (bottom-right): progress, title, one paragraph,
   Voltar / Mostrar / Pular buttons. Calls `onNext(step)` up to App.
3. `src/App.tsx` — glue: renders the dock when a logged-in identity exists and the tour isn't
   done/dismissed; `onNext` teleports via the ALREADY-EXISTING `handleSetMainView` (+ `setGamesSubTab`
   for games steps). Steps with `view: null` (settings/notifications pointers) don't teleport, they just
   advance text — that's how we stay non-scary: the app never yanks the user somewhere they didn't click for.

Resumable (index persisted per identity), skippable (one click, never asks "are you sure"),
never auto-reopens after dismiss/complete except via the HelpModal re-arm button.

```ts
import type { MainViewType } from '../components/home/HomeFooter';
import type { GamesNavTab } from '../components/home/SidebarNav';

export const TOUR_KEY_PREFIX = 'orbit_tour_v1:';

export type TourStep = {
  id: string;
  title: string;
  text: string;
  /** View to teleport to when the user clicks "Mostrar". null = pointer step, no teleport. */
  view: MainViewType | null;
  gamesTab?: GamesNavTab;
  /** Optional: element the copy points at, for a nudge hint line only. */
  pointsAt?: 'settings' | 'notifications';
};

export type TourState = {
  version: 1;
  index: number;
  status: 'active' | 'done' | 'skipped';
};

// Copy is final (humanized PT-BR). Do not "improve" it.
export const TOUR_STEPS: TourStep[] = [ /* filled in Task 5 */ ];

export function tourStorageKey(identityId?: string | null) {
  return `${TOUR_KEY_PREFIX}${identityId || 'anonymous'}`;
}

export function initialTourState(): TourState {
  return { version: 1, index: 0, status: 'active' };
}

export function readTourState(identityId?: string | null): TourState {
  if (typeof window === 'undefined') return initialTourState();
  try {
    const raw = localStorage.getItem(tourStorageKey(identityId));
    if (!raw) return initialTourState();
    const parsed = JSON.parse(raw) as Partial<TourState>;
    if (parsed.version !== 1) return initialTourState();
    const status = parsed.status === 'done' || parsed.status === 'skipped' ? parsed.status : 'active';
    const index = Number.isInteger(parsed.index) && (parsed.index as number) >= 0
      ? Math.min(parsed.index as number, TOUR_STEPS.length - 1)
      : 0;
    return { version: 1, index, status };
  } catch {
    return initialTourState();
  }
}

export function writeTourState(identityId: string | null | undefined, state: TourState) {
  if (typeof window === 'undefined') return;
  try {
    localStorage.setItem(tourStorageKey(identityId), JSON.stringify(state));
  } catch {
    // In-memory state stays usable when storage is unavailable.
  }
}

export function nextTourStep(state: TourState): TourState {
  if (state.index >= TOUR_STEPS.length - 1) return { ...state, status: 'done' };
  return { ...state, index: state.index + 1 };
}

export function isTourOver(state: TourState): boolean {
  return state.status !== 'active';
}

export function resetTour(identityId: string | null | undefined) {
  writeTourState(identityId, initialTourState());
}
```

## Retention logic (why this shape, for the implementer who asks)

- Dock, not modal: no scrim, no focus trap, app stays fully usable behind it. Scaring people off with a
  blocking wizard is the classic onboarding churn move; we avoid it on purpose.
- Teleport only on "Mostrar": user-driven jumps feel like a guide, automatic jumps feel like hijack.
- Resumable + skippable forever, no confirmation dialog on skip. A skipped tour that never nags is better
  than a completed tour that felt like a hostage situation.
- 10 steps, ~40 seconds: covers the loop (feed → create → earn → spend → social → infra) without a
  tour that outstays the user's patience.
- The copy sells specifics ("não volta", "sempre", "reinicia a janela"), not adjectives. Trust comes from
  admitting rough edges.
