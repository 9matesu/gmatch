## 1. Current context / assumptions

Read `AGENTS.md` and `docs/SPEC.md` before touching anything. Key facts verified in-code:

- `apps/desktop` — Electron 33 shell + Vite/React 19 renderer (`src/`), main process `electron/main.cjs` (568 lines). Renderer resolves the API via `apps/desktop/src/utils/api.ts::computeApiBase()` → `VITE_API_URL` | `window.__API_BASE__` (injected by `electron/preload.cjs` from the `--api-base=` argument) → fallback `http://127.0.0.1:8790`.
- **Sidecar:** `apps/desktop/electron/apiSidecar.cjs` spawns a system-installed `bun.exe` on port 8790 (SQLite snapshot + blob store in Electron `userData`). This is why a bare exe on another machine is broken today: no bun → dead API. `main.cjs` calls `apiSidecar.startApi()` unconditionally in `app.whenReady()`.
- **API:** `apps/api` — Hono on Bun (`src/serve.ts`, in-memory SQLite + periodic snapshot to `SNAPSHOT_PATH`, blob store at `BLOB_STORE_DIR`, WS at `/api/ws`). 45 migrations in `apps/api/migrations/`. No Dockerfile exists (fly infra was explicitly excluded from the orbit merge, SPEC §0). fly.io deploy is "prepared but parked, unauthenticated".
- **P2P today:** discovery is WS-swarm-based — `apps/desktop/src/hooks/useP2P.ts` learns peers from swarm messages over `/api/ws` (server-relayed) plus `localStorage['orbit_p2p_known_peers']`. Direct WebRTC payload fanout goes through `apps/desktop/src/utils/peer-relay.ts` (PeerJS, public cloud signaling, ICE-sanitized via `src/utils/ice-hygiene.ts`; TURN only if `NEXT_PUBLIC_TURN_*` env set — nobody sets it). **Because every desktop spawns its OWN local sidecar, two machines never share a WS room → cross-machine discovery is impossible today. Pointing all clients at one hosted server fixes the discovery topology by itself.**
- **Dead ends found (verified):**
  1. `apps/desktop/src/components/CardDetailView.tsx` ~L470–490: "List for sale / Cancel listing / Transfer feature coming soon" toasts — but the API already has `POST /api/cards/:id/list|cancel|buy|transfer` (`apps/api/src/routes/cards.ts` L51–99, service methods in `apps/api/src/cards.ts`).
  2. `apps/desktop/src/components/feed/SharePostModal.tsx::handleSendDirectShare` (L54) — fakes success with a toast, sends nothing. Real endpoint: `POST /api/pm/send` (`apps/api/src/routes/pm.ts` L82).
  3. Same file `handleCopyLink` — copies dead URL `https://goonmatch.fly.dev` (root, not even the post).
- **E2E is red:** `apps/desktop/test-results/.last-run.json` → `status: failed`, 2 failed Playwright journeys (traces in `test-results/`).
- **Lint/test gate:** `npm run lint` (0 errors) + `npm run test` (vitest, all workspaces) is the merge gate per AGENTS.md.
- **Hygiene:** hundreds of untracked `test-blobs-*` dirs pollute the repo (gitignored, but they slow everything; `TMPDIR` is already pinned to `I:/tmp` in `playwright.config.ts`).
- bun 1.4.0 is installed on the dev box (`%APPDATA%\npm`). Tests for the API run under vitest with `apps/api/src/test-utils.ts` helpers; desktop UI tests use RTL+jsdom (`apps/desktop/src/test/setup.ts`).

**Assumption:** "full social media suite" = everything already scaffolded in the shell (feed posts, stories, comments, likes, follows, profiles, DMs + groups + read receipts + attachments, share, explore/search, slideshows, lootboxes, card duels + marketplace, hacks/domination, moderation, admin panel) must be *reachable and functional* against the hosted backend — NOT new features. The plan adds wiring for the known fakes + a discovery roster endpoint, then journey-tests every surface.

## 2. Architecture / proposed approach

Deploy `apps/api` as one fly.io app with a persistent volume (snapshot DB + blobs at `/data`), expose it as the single "official server". The packaged Electron app becomes a thin client: a new `electron/release-config.cjs` holds the server URL, main skips the sidecar when `app.isPackaged`, and preload injects `--api-base=<official>` — reusing the existing `__API_BASE__` plumbing verbatim. Offline-capable pieces stay local by design (idle booru feed via IPC in `main.cjs`, image cache, idle save in localStorage). Dead ends are wired to the existing API; a new `GET /api/users/online` roster makes discovery instant on join; TURN gets a sane default so WebRTC works across NAT without config. electron-builder `portable` target + GitHub Actions on tag = the one-time .exe.

```
[portable.exe Electron] --https+ws--> [fly api (Hono/Bun, /data volume)]
       |                                     ^
       +-- local IPC booru/image cache       |  other players' exes (same URL)
                                             +-- WS swarm = peer discovery
```

## 5. Risks, tradeoffs, open questions

1. **OpenRelay TURN is a free public community server** — rate-limited, no SLA, and (privacy tradeoff) traffic transits a third party. Mitigation: env `NEXT_PUBLIC_TURN_*` overrides it, so you can drop in a coturn on fly later without a code change. Fallback already exists: even if WebRTC never opens, the WS-relay swarm carries all payloads (that's the no-dead-end guarantee; document in SPEC §10c amendment).
2. **PeerJS signaling still uses the public `0.peerjs.com` cloud** (`peer-relay.ts` L36 `new Peer(id, { config })` — no host option). IDs are sanitized Ed25519-derived, ICE is hygiene-gated, and messages are encrypted (`@orbit/crypto`), so exposure is metadata-only. Self-hosting a `peer` PeerServer on fly is the follow-up if that's unacceptable for 1.x. Flag to user; do NOT block the release.
3. **Single server = single point of failure.** Hosted-only was chosen knowingly; the desktop keeps working solo (idle game uses local IPC booru + localStorage save; shell shows offline states). Snapshot-on-write means a crash loses ≤30s of ledger.
4. **Unsigned exe → SmartScreen warning** on first run. Options for the user (open question, not in 1.0 scope): ~$100–400/yr OV code-signing cert, or accept the "More info → Run anyway" flow documented in README.
5. **fly.io requires the user's authenticated CLI + a payment method** for the volume — hard stop at 1.3; nothing else in the plan depends on completing it (dev-stack tests pass locally; only 5.3's online pill needs a live server).
6. **API deps `@orbit/*: "*"`** may bite under `bun install` outside the workspace root (1.1) — the plan's fallback (`file:` relative deps) changes shared dep resolution; run the FULL test suite after that change, not just the API's.
7. **vite `base: './'`** can break if any code assumes absolute asset URLs — verified by journey suite run against `npm run build` output (`vite preview`) before packaging.
8. **YAGNI list** (explicitly NOT in 1.0): card listings UI beyond list/cancel/transfer/buy (market browsing exists), discord bridge, mobile PWA (`public/manifest.webmanifest` legacy — leave dead, don't wire), auto-updater.
