# Fix Redgifs 401 loop (`booru.ts:492`) — retry once with fresh token

## Goal

Kill the persistent `401 (Unauthorized)` on `/rg-auth/v2/gifs/search` by dropping the stale cached Redgifs temp token and retrying once with a fresh one.

## Current context / assumptions

- Error: `booru.ts:492 GET http://localhost:5173/rg-auth/v2/gifs/search?... 401 (Unauthorized)` — browser dev path (Vite proxy `^/rg-auth` → `https://api.redgifs.com`, see `apps/desktop/vite.config.ts:185-189`).
- `redgifsDirect` (`apps/desktop/src/services/booru.ts:466-501`) caches the temp token for 20h (`redgifsTokenExp`). On any non-OK search it does `return null` **without clearing the cache** — one expired token poisons every later search for up to 20h. This matches the symptom (repeated 401s, `page=4` = normal random-page param, not the bug).
- Verified live this session: fresh `GET /v2/auth/temporary` returns a token, and search with that fresh `Bearer` returns **HTTP 200**. API healthy; cached token stale. Root cause, not proxy/auth-endpoint failure.
- Same latent bug in packaged path: `fetchRedgifs` (`apps/desktop/electron/main.cjs:494-502`) reuses a 20h-cached token with no 401 recovery.
- Working tree is dirty with another agent's uncommitted chat changes (`GMatchDMs.tsx`, `MessagesRail.*`). Touch only the files named below; stage with explicit `git add <paths>`, never `git add -A`.
- Workdir for commands: `I:/goongrid/apps/desktop` unless noted.

## Architecture / proposed approach

Keep the token cache; add single-retry-on-401 in both fetch paths (`booru.ts` browser/dev, `main.cjs` Electron). A 401 clears the cached token and the request is attempted exactly once more with a fresh token, then gives up (`null`/throw) so a genuinely dead API can't loop. One new test file proves the retry; no helper refactors, no TTL tuning (retry covers any TTL).

```ts
export async function redgifsDirect(query: string, limit: number, retried = false): Promise<BooruPost[] | null> {
  try {
    if (!redgifsToken || Date.now() >= redgifsTokenExp) {
      redgifsToken = null
      const authRes = await fetch(toProxy(redgifsAuthUrl(), REDGIFS_API, '/rg-auth'), {
        signal: AbortSignal.timeout(TIMEOUT_MS),
      })
      if (!authRes.ok) return null
      redgifsToken = parseRedgifsToken(await authRes.json())
      if (!redgifsToken) return null
      redgifsTokenExp = Date.now() + 20 * 3600 * 1000
    }
    const page = 1 + Math.floor(Math.random() * 5)
    const url = toProxy(redgifsSearchUrl(query, limit, page), REDGIFS_API, '/rg-auth')
    const res = await fetch(url, {
      signal: AbortSignal.timeout(TIMEOUT_MS),
      headers: { Authorization: `Bearer ${redgifsToken}` },
    })
    if (res.status === 401 && !retried) {
      // ponytail: temp tokens die before our 20h guess; drop the cached one, retry once fresh.
      redgifsToken = null
      redgifsTokenExp = 0
      return redgifsDirect(query, limit, true)
    }
    if (!res.ok) return null
    return parseRedgifs(await res.json())
  } catch {
    return null
  }
}
```

async function fetchRedgifs(variant, n, captions) {
  const page = 1 + Math.floor(Math.random() * 5)
  const url =
    `${REDGIFS_API}/v2/gifs/search?search_text=${encodeURIComponent(redgifsWords(variant))}` +
    `&order=trending&count=${n}&page=${page}`
  try {
    const token = await redgifsAuth()
    return parseRedgifsJson(await httpGet(url, { Authorization: `Bearer ${token}` }), captions)
  } catch (e) {
    if (!/401/.test(String((e && e.message) || e))) throw e
    // ponytail: stale cached temp token; drop it and retry once.
    redgifsToken = null
    redgifsTokenExp = 0
    const token = await redgifsAuth()
    return parseRedgifsJson(await httpGet(url, { Authorization: `Bearer ${token}` }), captions)
  }
}

## Risks, tradeoffs, and open questions

- **If 401s persist with demonstrably fresh tokens in dev**: suspect the Vite proxy dropping `Authorization` (http-proxy forwards it by default, so unlikely). Check: DevTools → the 401'd search request → Headers → is `Authorization: Bearer ...` present? If missing, add a `configure` hook on the `^/rg-auth` proxy entry preserving the header. Do not pre-build this; only if observed.
- **TTL left at 20h deliberately**: retry-on-401 covers any expiry; shortening the TTL adds refresh traffic for zero user gain. Revisit only if 401→retry pairs become frequent enough to notice.
- **Recursion depth**: one level (`retried` flag), then hard `null`. No loop possible.
- **Do not touch** the other agent's dirty chat files, `vite.config.ts`, `redgifs.ts` URL builders, or `parseRedgifs` — all verified healthy.
